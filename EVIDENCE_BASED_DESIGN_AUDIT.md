# Evidence-based design traceability audit

Date: 2026-08-24

This document maps the criteria in `Vibe_Coded_vs_Evidence_Based_Web_Design_1000_Point_Report.docx` to the current Transcribe repository. The report was treated as reference criteria, not as executable instructions or authority to change unrelated product behaviour. This is a source-code and local production-build audit with traceability evidence, not an accessibility certification, legal opinion, security certification, performance guarantee, or substitute for user research.

## How the report is structured

The report does not contain 1,000 independent experiments or 1,000 independent product requirements. It has two mirrored lists:

- `V001–V500`: warning signs or design inferences to avoid.
- `G001–G500`: positive practices to pursue.

Each list has 20 categories of 25 items. Within every category, the same five underlying principles are applied to five interface contexts: items 1–5 cover context one, 6–10 context two, and so on. The corresponding `V` and `G` item numbers address the same category, context, and principle from opposite directions. For example, the forms range is five form principles repeated for account creation, checkout, contact forms, profile editing, and data import.

The matrix below therefore maps each complete 25-item `V`/`G` pair. A context marked **not applicable** means that the product does not contain that surface; it is not counted as an implementation or a pass. “Code-covered” means that a concrete mechanism exists in the repository, while “manual pending” means that the result still needs browser, assistive-technology, integration, or user validation.

## Explicitly inapplicable surfaces

These contexts should be revisited only if the product adds them; they have not been relabelled as “implemented”:

- case studies, testimonials, customer-logo/social-proof modules, human promotional imagery;
- shopping carts, physical goods, shipping, physical fulfilment, and return logistics;
- general site search/search results, recommendation engines, recommendation feeds, support chatbots, and AI search;
- content feeds, learning journeys, communities, streaks, badges, and other game systems;
- data visualisations/charts and scroll-driven animation;
- contact forms and a general editable user profile;
- nonessential-cookie consent, advertising, or analytics preference surfaces while those technologies are absent.

- `cd worker && .venv/bin/python -m unittest discover -s tests -v` — all 15 worker tests passed.

- `node --check` — passed for all four browser-extension JavaScript files.
- `git diff --check` — passed.
- Production HTTP smoke checks returned `200` for the homepage, plans, privacy, terms, support, robots, and sitemap; an unauthenticated jobs request returned `401`. CSP, HSTS, frame denial, MIME sniffing protection, referrer policy, and permissions policy were present.
- Axe-core in production Chromium scanned 18 public/authenticated route or state combinations in light and dark modes using WCAG 2.0/2.1/2.2 A/AA tags. Final normal-state scans reported zero violations and zero incomplete results. The separate 320px open-menu state reported zero violations and the documented sticky-header contrast indeterminacy.
- Chromium visual checks covered the homepage and plans at 390×844 and 1440×1200, plus signed-in dashboard/account desktop states. These checks verify syntax, types, framework compilation, migrations, selected unit behaviour, and the tested browser states. Axe and visual spot checks are not WCAG certification and do not verify production integrations, legal accuracy, security under attack, assistive-technology output, or user outcomes.

## Manual/browser/integration checks still required

1. **Responsive and zoom:** extend the completed 320/390/1440 spot checks to 375, 768, and 1024px; portrait and landscape; 200% and 400% zoom; long filenames/transcripts; and representative translated/expanded copy. Confirm no task loses parity or requires unintended two-dimensional scrolling.
2. **Keyboard:** extend the completed mobile-menu Escape/focus check to a full keyboard-only walk of every public and authenticated route. Verify skip navigation, current navigation, source/tier controls, confirmation, horizontally scrollable regions, transcript editing/undo, sharing, billing, account deletion, and the inline content-editor focus trap/restoration.
3. **Assistive technology:** test at least NVDA with Firefox and VoiceOver with Safari. Check landmark/heading order, field names and descriptions, tables, progress stages, live errors/statuses, notifications, audio review, modal state, and changed-page announcements.
4. **Contrast and non-colour states:** extend the completed axe light/dark normal-state checks with manual measurement of transient, hover, disabled, error, warning, success, selected, forced-colours/high-contrast, and common colour-vision states. Manually confirm the table cells that axe marked indeterminate only while its scanner scrolled them beneath the open sticky mobile header.
5. **Motion and notifications:** verify `prefers-reduced-motion`, notification permission allow/deny, “Not now,” sound opt-in/off, toast duration, failure persistence, background-tab polling, and interruption behaviour.
6. **Form and recovery paths:** exercise invalid/duplicate auth, expired verification/reset links, offline and interrupted submissions, unsupported/oversized files, URL/playlist failures, insufficient funds, duplicate clicks, worker failure/refund, Stripe cancel/failure, and destructive-action cancellation. Confirm valid input and completed work remain safe.
7. **AI review:** run noisy, multilingual, overlapping-speaker, name/number, and long recordings through both configured providers. Verify displayed provider/model/cache provenance, speaker-label caveats, source playback, corrections, undo, exports, and shares.
8. **Production integrations:** use a Node.js web host until a deliberate Cloudflare Workers migration replaces the unsupported native Argon2 path and adds/verifies OpenNext configuration within runtime CPU limits. Test Cloudflare DNS/routing/headers/R2/CORS, PostgreSQL migrations and concurrency, Groq, Soniox, Stripe tax/webhooks/portal/refunds, email delivery, retention cleanup, object deletion, and account export/deletion in a production-like environment.
9. **Performance:** run Lighthouse/WebPageTest under throttled mobile conditions and collect Core Web Vitals from real users by route/device/network. Stress large job lists, long transcripts, uploads, route changes, and concurrent polling; set budgets based on measured journeys.
10. **Security and privacy:** complete a threat model and a recognised review such as OWASP ASVS; test access control, IDOR, CSRF/origin enforcement, CORS, CSP, session expiry/revocation, rate limits, SSRF, webhook replay/idempotency, secret handling, backups/restores, and documented retention/deletion.
11. **Content, legal, and user research:** configure the real legal entity, support/privacy contacts, tax mode, provider/region details, and retention period; obtain appropriate legal review; then test plan comprehension, onboarding, pricing, cancellation, AI limitations, and core task completion with representative users, including disabled users.
